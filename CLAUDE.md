# CLAUDE.md

## Project
- Reproduce Gagnon et al., *Sci Data* 2026 (doi 10.1038/s41597-025-06499-z), the UCSD-PTGBM post-treatment high-grade glioma dataset on TCIA (doi 10.7937/fwv2-dt74, CC BY 4.0).
- Then predict **PFS** from the **first post-surgery timepoint**: the first scan 0–90 days after initial surgery, the paper's survival-subset rule.
- Inputs are **clinical variables only** for now. Imaging comes later.

Status:
1. Repo scaffold: done.
2. OS/PFS cleaning: done, with open questions.
3. Paper reproduction: partial.
4. Clinical PFS modeling: not started (`ucsd_pfs/modeling/` holds stubs).

## Environment and commands
- Use `uv` only: `uv sync`, then `uv run ...`. Never use pip or create venvs.
- `make data`: downloads the v1 and v3 clinical xlsx plus the negative-cases xlsx into `data/raw/`, and writes `data/interim/clinical_timepoints.parquet`.
- `make clean-survival`: writes `data/processed/{timepoints,survival_patients}.parquet` and logs the QC summary.
- `make reproduce`: writes `reports/tables/{table1,fig2}_reproduction.csv` and `reports/figures/fig2_*.png`.
- `make notebooks`, `make test`, `make lint`, `make format`.
- Every module is also a typer CLI: `uv run python -m ucsd_pfs.<module>`.
- A GPU is present, but nothing here needs it yet.

## Dataset gotchas (read before touching clinical data)
- Sheet name `Cinical info` (sic). Several headers end in a space, so strip them. The `Data Dictionary` sheet has about 1M blank rows. Use `dataset.read_clinical_raw` / `clean_clinical`.
- All `Days from Acquisition to …` columns are offsets from **that row's scan date**, so they differ between timepoints of the same patient. Use `timeline.add_timepoint_times` to get days since initial surgery (`t_*`).
- **The v3 OS/PFS columns are wrong.** v3 is v1 with all columns except ID/BraTS ID/age row-permuted. OS/PFS were correct in v1 and got moved. The interim table takes OS/PFS from v1 by ID (v1 OS matches the v3 dates 60/62, v3 OS matches 0/61). `v3_*` columns are kept for audit only.
- **Never build survival targets from raw columns.** Use `data/processed/survival_patients.parquet` (`os_days`, `os_event`, `pfs_days`, `qc_flags`, `in_provided_subset`) and `survival.pfs_target(df, mode)`.
- PFS has **no event flag** and can't be rebuilt from dates. Whether a missing PFS means censored is an open question, so always state the `pfs_target` mode (`events_only` or `censor_at_last_followup`) and report both when it matters.
- The cohort is 96 patients by the paper's rule, 85 of them with provided OS/PFS. The paper says 94. Remaining discrepancies (sex counts, Fig. 2 p-value) are listed in `references/survival_cleaning.md`.

## Modeling rules (for the next step)
- **No leakage:** features may only use information available at the cohort scan. Exclude death, follow-up, OS, treatment dates after the scan, and `has_tumor`/negative-case labels (judged with later imaging).
- **Small N (about 85–96):** use repeated stratified K-fold, no single split. Report C-index (Harrell and Uno) with confidence intervals. Fix seeds via `config.SEED`.
- Planned models: lifelines (KM, CoxPH), scikit-survival (CoxNet, RSF, GBSA), and sklearn baselines (regression on log-PFS, classification of PFS > 6 months).
